# M1 test results

Recorded 2026-11-17 on the author's machine (Intel Core i7-13700H, Windows 11, Python 3.14.5 in
the repo's `.venv`; pytest 9.2.0, pytest-timeout 2.4.0, ruff 0.17.5, mypy 2.4.1, pip-audit 2.10.1).
Every run on this machine read only copies of `tests/fixtures/host` under the repo's `.tmp/`;
the machine's own files were never baselined, scanned or watched. CI re-runs the suite on Ubuntu
with Python 3.12, runs the Linux-only tests and the demo with the inotify backend; CI has **not
been run yet** (the repository is not pushed).

## Demo: live watch on a copy of the fixture host (`python scripts/demo.py`)

Polling backend, 0.1 s interval, Windows. Latency is measured with `time.monotonic` from just
before each change is written to the alert callback.

| Step | Alert | Latency |
|---|---|---|
| new SSH key for root | critical, content, `/root/.ssh/authorized_keys` | 120.5 ms |
| modified binary | high, content, `/usr/sbin/sshd` | 131.3 ms |
| new cron job | critical, added, `/etc/cron.d/updater` | 120.3 ms |
| setuid bit on a binary | critical, mode, `/usr/bin/ls` | 129.7 ms |
| new user with an SSH key | critical, added, `/home/eve/.ssh` and its `authorized_keys` | 130.8 ms |
| shadow file owner changed | critical, owner, `/etc/shadow` | 148.5 ms |

Result: 6 of 6 detected, median 130.2 ms, max 148.5 ms, 7 alerts, 1 full scan. The demo ran
two more times inside `.tmp/check.sh`: median 443.1 ms and max 1020.5 ms while six other agents'
builds and tests were running on the machine (one step just over the 1 s target in RFC 0001), and
median 145.6 ms, max 149.8 ms in the second gate run. All three runs detected 6 of 6. The follow-up
`scan` of the same copy reports the same 7 paths (6 critical, 1 high) in 0.043 s over 30 entries.
The new cron file is critical here, not high, because Windows reports new files as mode 0666,
which is world-writable, so the escalation rule applies; on Linux with umask 022 it would be high
(the CLI test pins its mode to 0644 so the result is the same on both).

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | Changes to critical Linux files go unnoticed; M1 counts when a sealed baseline records hashes, modes and owners of the covered files, and changes are reported in real time with full scans as the safety net ([RFC 0001](../rfc/0001-design.md), CTQ table). |
| Measure | 129 tests, the six-step demo (6 of 6, median 130 ms with polling at 0.1 s), ruff, mypy `--strict`, pip-audit, 14 hand mutants, on an Intel Core i7-13700H with Windows 11. |
| Analyze | The first suite let two mutants survive: removing the `.fim-meta` filter (no test listed the tree root) and not asking for new watches on a new directory (the test's batch also held an `IN_IGNORED` event, which set the same flag). One test input (`"99999"` as a mode) checked the wrong error path. The polling watcher's blind spot (same size, restored mtime) is real and is documented, not hidden. |
| Improve | Added `test_a_top_level_glob_never_reports_the_fixture_manifest` and `test_a_new_directory_alone_asks_for_new_watches`; both mutants are now killed. The mode test uses `"17777"` (valid octal, out of range) and `"9"` separately. |
| Control | `.tmp/check.sh` and CI run lint, strict types on both platforms, the tests and `pip-audit` on every change; CI adds the Linux-only tests and the inotify demo; actions are SHA-pinned and Dependabot PRs are paused. |

## How to reproduce

```bash
python -m venv .venv && .venv/Scripts/activate      # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"
python -m pytest -q -rs
python -m pytest -q -rs -m linux                    # Linux only
python scripts/demo.py                              # --backend inotify on Linux
fim baseline --root tests/fixtures/host --out .tmp/b.json && fim scan --root tests/fixtures/host --baseline .tmp/b.json
```
