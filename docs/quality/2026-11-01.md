# Quality check against the 10 rules (2026-11-01 rule set, applied while building M1)

Run on 2026-11-17 on Windows 11 (Intel Core i7-13700H) with Python 3.14.5 in the repo's `.venv`.
Only copies of `tests/fixtures/host` under the repo's `.tmp/` were read and changed; the Linux-only
tests are CI-only (not run yet). Mutations were applied one at a time by a scratch script that
restored each file right after its test run (the script is not kept in the repository).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | No network calls. File reads: a missing path is `None`, any other `OSError` while reading becomes an entry with `error` (reported as `unreadable`, never as unchanged); a directory that cannot be listed is reported (`Tree.walk` errors). inotify: `inotify_init1` and `inotify_add_watch` failures raise `InotifyError` (watch limit with a clear message); per-directory failures other than "gone" are kept in `errors`; truncated event buffers raise. `select` has a timeout, so `watch` never blocks forever. The CLI maps input errors to exit 2 and read errors to exit 3. ruff `BLE`, `E722`, `S110` enabled; no bare or broad `except` in `src/`. Tests: `test_parse_events_rejects_truncated_records`, `test_a_file_swapped_between_lstat_and_open_is_an_error`, `test_unlistable_directory_is_reported_not_skipped` (CI), `test_bad_input_exits_two`. |
| 2 | Writes safe to retry | pass | The baseline and the JSON scan report are written via a temp file in the same folder, `fsync` and `os.replace` (`baseline.write_atomic`); the temp file is removed on failure (`test_failed_write_leaves_no_temp_file_and_keeps_the_old_file`, `test_save_is_atomic_and_rewrites_identically`). The alert log is append-only, one `write` per record plus `fsync`; replaying it on start restores the open states, so a restarted monitor writes no duplicate (`test_alert_log_replay_prevents_duplicates_after_a_restart`, `test_watch_with_the_poll_backend_reports_alerts_and_writes_the_log`). Watched trees are never written. |
| 3 | No race conditions | pass | `Monitor._emit` runs the check-then-write of the open-state table under a lock; `test_concurrent_checks_emit_one_alert_per_state` runs four threads on the same change and gets one alert. A file swapped between `lstat` and `open` is detected by comparing device and inode (TOCTOU), and opened with `O_NOFOLLOW`. New directories are walked after their watch is added, so files created before the watch existed are still seen. |
| 4 | Don't trust the clock | pass | Durations (`scan`, `baseline`, the demo latency, the monitor schedule) use `time.perf_counter` or `time.monotonic` (the monitor's clock is injectable; `test_run_scans_at_start_on_schedule_and_on_overflow` uses a fake one). Stored times (`created_at`, alert `at`) are `datetime.now(UTC)` and end in `+00:00` (asserted). Change detection never uses mtime as truth: the polling watcher uses it only to decide what to re-hash, and the full scan hashes everything (`test_full_scan_catches_a_change_with_size_and_mtime_restored`). |
| 5 | Read before changing | pass | The code reads no environment variables; every input is a CLI flag documented in the README. Standard-library APIs only (`tomllib` 3.11+, `os.O_NOFOLLOW`/`O_NONBLOCK` via `getattr` for Windows, `ctypes.CDLL(None)` and the libc `inotify_*` functions on Linux); mypy `--strict` passes with `--platform win32` and `--platform linux`. inotify constants match `<sys/inotify.h>`. Every path in the docs exists (`audit_repo.py` link check). |
| 6 | Never break compatibility | pass | First release. Policies and baselines carry `version = 1` and loaders refuse other versions and unknown keys, so a future format is an explicit change. Alert records carry a `type` field (`alert`, `resolved`). |
| 7 | One source of truth | pass | The policy used by `scan` and `watch` is the copy stored (and sealed) inside the baseline, not a file that could drift. Coverage is decided only by `Policy.group_for`; the walk, the watcher and the monitor all call it. The fixture's modes and owners live only in `.fim-meta/stat.tsv`, reloaded when it changes. The alert log is the source of open states; the in-memory table is rebuilt from it. Python >=3.11 in `pyproject.toml`, 3.12 in CI, 3.11+ in the README. |
| 8 | Small changes, no secrets, validate input | pass | Fixture keys are `EXAMPLE-NOT-A-REAL-KEY`, `/etc/shadow` holds only `*` and `!`, "binaries" are inert text. Validated input: policy (schema, size cap 256 KiB, names, severities, absolute paths without `..`, `.`, empty parts, control characters or backslashes, `/` refused), manifest lines and size (4 MiB), baseline (size 512 MiB, format, seal before use, every entry field), key length (16+ bytes), alert-log records and size, numeric flags with ranges, root (a directory; off Linux not a drive root). No runtime dependencies. |
| 9 | Tests that can actually fail | fixed | No tautologies and no unexplained skips: Linux-only tests are deselected by the `linux` marker and run in CI; four off-Linux refusal tests skip on Linux by design. While writing the tests, two weak assertions were caught and replaced before the first green run (a `... or True` and an `or` fallback in a set comparison). One input (`"99999"`) tested the parse error instead of the range check; it now uses `"17777"` and `"9"` separately. 14 hand mutants: 12 killed by the first suite, 2 survived and were killed after adding tests (table below). |
| 10 | Re-verify | pass | ruff, ruff format, mypy `--strict`, 129 tests, pip-audit, `.tmp/check.sh` (CHECK PASS) and `audit_repo.py` (OK) re-run after the last change. CI not run yet (repository not pushed). |
